`src-tauri/` owns the Tauri host: plugins, thin commands, domain modules, helpers, permissions, and bundled platform-tools. Frontend must reach this only via IPC.

## ADB access (`src/adb/`)

`AdbClient` is the **only** sanctioned way to run `adb`. Do not add a fresh `Command::new(adb)` and do not hand-roll exit markers.

```text
adb/
├── mod.rs        AdbClient · CmdOutput · nonce markers · batch splitting
├── telemetry.rs  collect() → DeviceTelemetry
└── parse.rs      getprop · dumpsys battery · /proc/meminfo · df · ip addr · uptime · wifi
```

| API | Use for |
| --- | --- |
| `AdbClient::new(&app, serial)` | Cheap per-operation construction. Blank/whitespace serial ⇒ "no device selected". |
| `.shell(cmd)` / `.shell_checked(access_root, cmd)` | One device-shell command, strict exit checking. Host success ≠ device success (`adb shell false` exits 0 on the host). Returns cleaned output with the marker line stripped. |
| `.shell_batch(&[cmd, …])` | **N device reads in one `adb` process.** Prefer this whenever you need more than one property. A non-zero command does *not* fail the batch — inspect `CmdOutput::exit_code` / `is_success()` / `ok_stdout()`. `exit_code == None` means the marker never appeared: neither output nor status is trustworthy. Only host-level failure returns `Err`. |

Rules:

- Binary path + working directory are resolved **once per process** into a `OnceLock`. Do not re-resolve per spawn.
- Markers are per-batch nonces (pid + counter + nanos) so device output cannot forge a command boundary. Never replace them with a fixed literal.
- The joined batch script travels as a single argv entry — batch tens of commands, not thousands.
- `helpers::adb_shell_checked` is a compatibility forwarder into `AdbClient::shell_checked`. Existing callers may keep using it; new code constructs an `AdbClient`.
- Telemetry (`get_device_telemetry`) batches 9 device commands into 1 `adb` process and returns **typed numbers**, not display strings. Formatting is a frontend concern. New device reads follow that shape rather than extending the legacy string-formatting `get_device_info`.

## Module invariants

- Commands return `CmdResult<T> = Result<T, String>` unless a documented exception exists.
- Long-running / blocking work: `async` + `spawn_blocking` or `block_in_place` as appropriate.
- **Thin commands** — real logic in domain modules, `src/adb/`, or `helpers.rs`.
- IPC structs: `Serialize` + `#[serde(rename_all = "camelCase")]`. Tagged enums rename tag **values** too.
- `resolve_binary_path()` for bundled ADB/fastboot. Emulator binary is **not** bundled — SDK resolver.
- Critical shell ops: `AdbClient::shell_checked` (or `helpers::adb_shell_checked`) — host OK ≠ shell OK.
- Filenames: `sanitize_filename` / `safe_image_file_name` before joining user or manifest names.
- Remote HTTP: no auto-follow redirects; `validate_outbound_url` every hop (payload + marketplace + Magisk + host setup).
- Host setup: Windows-only official Google catalog; platform-tools and USB driver are **separate** UAC actions; Machine Path is HKLM (not process env); the app still uses bundled ADB.
- Debloat: device-serial-keyed cache; refuse destructive actions when SDK unknown; no Disable on API &lt; 23.
- Permissions: every `generate_handler!` command in `permissions/autogenerated.toml` `commands.allow` (no orphans).
- File Explorer host drop: `host_path_kinds` is a thin host `Path::is_dir` classify (cap 256). Import still uses `push_file`; device moves still use `transfer_device_files`. Do not add a second ADB push loop in Rust for OS drops.
- Payload: domain invariants live in `src/payload/AGENTS.md` (streaming/mmap, dynamic partitions, delta differential patching, transaction safety, sparse IOCTL threshold $\ge 64\text{ KiB}$).
- Firmware Hub: real-time OEM scrapers (`GooglePixelScraper` with ToS cookie bypass); two-tier cache (RAM `RwLock` + 24h disk JSON TTL); fallback to stale cache on network failure.
- Marketplace install: selected serial + owned temp download path only. `marketplace_download_apk(app, url, package_name?, download_id?)` streams via `install_queue::download_apk_streaming` → throttled `marketplace:download-progress` (8 Hz, `DownloadProgressPayload {packageName, downloadId, bytesDownloaded, totalBytes, speedBps, percentage, etaSeconds}` over `camelCase` serde) + `create_download_client` (300s, pool 8, `limited(5)` redirects, tcp_nodelay). Guard is `install_queue::is_owned_marketplace_download`.
- Marketplace cache: SWR via `cache.rs` — `SwrEntry {fresh_ttl, stale_ttl}` with `SwrStatus::Fresh/Stale/Miss`; `get_search_swr` (fresh 3m / stale 30m, max 200) and `get_detail_swr` (fresh 10m / stale 60m, max 500), plus `verified_apks: HashMap<String,RepoApkStatus>` (positive 12h / negative 2h, max 1000) memoising APK-existence; callers in `commands/marketplace.rs` return stale rather than blocking.
- Marketplace resolver: `resolver.rs` `resolve_github_repo` (slug/URL sync) + `resolve_github_repo_dynamic(client, id, download_url?, repo_url?, token)` async chain — F-Droid `sourceCode` API → GitHub search `"<package_id>" topic:android`. `extract_repo_from_url` handles `github.com/`, `raw.githubusercontent.com`, `api.github.com/repos/`, `git@github.com:`.
- Marketplace assets: `assets.rs` `is_apk_asset` (only `.apk`, excludes `.aab/.xapk/.apks/.sig/.sha256`, alpine `alpine-`/`_alpine`, `androidTest`) + `classify_abi` (arm64-v8a 100 > universal 80 > generic 70 > armeabi-v7a 60 > x86_64 40 > x86 20) + `rank_and_select_best_apk` (score +10 for `release`/`stable`, -15 for `debug` except `github-debug`). Used by `github::verify_apk_availability` and `get_detail`/`list_releases`.
- Marketplace markdown: `markdown.rs` `enrich_readme_markdown` rewrites relative `![alt](path)` → `raw.githubusercontent.com/{owner}/{repo}/{branch}/...` and `[text](path)` → `github.com/{owner}/{repo}/blob/{branch}/...`, rewrites `<img src>`, flattens `<details>/<summary>` → `###`, guards fenced code-blocks. `github::fetch_readme` dual-path: `GET /repos/{slug}/readme` with `Accept: application/vnd.github.raw` then raw CDN fallback (`head`/`main`/`master` × 6 filenames) + pre-release fallback (`/releases/latest` 404 → `/releases?per_page=5`).
- Marketplace HTTP client: `ManagedHttpClient` tuned (`connect_timeout 2500ms`, `timeout 10s`, `pool_max_idle_per_host 32`, `idle 180s`, `tcp_nodelay true`, `http2_adaptive_window`, keep-alive 15s/5s) for bursty provider calls. Download client separate (`install_queue` 300s/15s, pool 8).
- Apps telemetry: `apps/telemetry.rs` trims surrounding `"`/`'` on CSV package lists and filters `storageBreakdown` to user packages only (skip system pkgs; when `user_pkgs` non-empty require membership).
- Emulator AVD discovery: `~/.android/avd/*.ini` (not `emulator -list-avds`). Root proof: `verify_avd_root` / `su -c id -u == 0`.
- Clippy bar: package `[lints]` + `clippy.toml`; CI uses `-D warnings`.

## Build profiles

`[profile.release]`: `opt-level = 3`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`.

- The workload is **CPU-bound** (sha2, inflate/zstd/lzma, large memcpy). `opt-level = "s"` disables loop vectorization and most unrolling — exactly what the extract path needs — so it must not be reinstated for a smaller binary.
- The separate `release-fast` profile was deleted: `release` now *is* the speed profile. Do not re-add it or pass `--profile release-fast`.
