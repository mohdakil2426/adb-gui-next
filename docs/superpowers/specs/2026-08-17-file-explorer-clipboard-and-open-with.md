# File Explorer clipboard, Open with, and shortcuts

Date: 2026-08-17  
Status: approved in chat; implement via `docs/superpowers/plans/2026-08-17-file-explorer-clipboard-open-with.md`

## Goal

Make File Explorer feel like Windows Explorer for the three gaps that remain after the chrome pass: in-app copy/cut/paste/move on the **same device**, Open with (VS Code / Notepad / host Explorer) plus **push-on-save** for editors, and a Windows-first keyboard surface that still uses Ctrl/Cmd on other desktops.

## Non-goals

- Putting Android files on the OS file clipboard (`CF_HDROP` / Nautilus URIs).
- Merging concurrent phone + PC edits.
- Auto-sync of binaries or huge files.
- macOS as a first-class build (code paths may exist; builds stay paused).
- New charting libraries or other unrelated deps.

## Clipboard (same serial)

- Session-only clipboard in File Explorer React state: `{ serial, mode: 'copy' | 'cut', sources: string[] }` (absolute device paths).
- Ctrl/Cmd+C / X / V when the files view is active and focus is not an input.
- Context menu: Copy, Cut, Paste, Copy path (`Ctrl+Shift+C` copies the POSIX path as text via the existing clipboard plugin).
- Paste target = current directory. Same-folder **cut** is a no-op. Same-folder **copy** is refused with a toast (no “file - Copy” names in v1).
- Backend: `copy_device_files` / `move_device_files` using quoted `cp -a` / `mv` through `AdbClient::shell_checked` / existing `run_shell_for_mode`. Validate every path with `validate_write_path_for_mode`. Root vs normal follows `getFileAccessMode` on the **destination** (and each source).
- If any destination exists and `overwrite` is false, copy/move **nothing** and return `skippedExisting: string[]`. UI shows Replace / Cancel; Replace retries with `overwrite: true`.
- After a successful **cut** paste, clear the clipboard. Copy paste keeps it.
- Serial mismatch (clipboard from another device): toast and do not paste.

## Open with + push

- Double-click / Enter on an allowlisted text file keeps today’s pull, but **Open with** is explicit: Visual Studio Code, Notepad (Windows) / gedit|kate|xdg-open (Linux), Show in Explorer (`explorer /select,` on Windows; `xdg-open` parent dir on Linux).
- Local copy lives under `%TEMP%/adb-gui-next-editors/` with a **unique** name derived from serial + remote path (not basename-only).
- VS Code and Notepad (or Linux GUI editor) start a **watch session**: poll mtime+hash ~500ms, debounce, `push_file` / existing root staging. Emit `files:edit-pushed`. Stop on serial change, new open of the same remote, or app exit.
- Show in Explorer does **not** start a watch.
- Status: toast + log on first successful push after a save; errors via `handleError`. Optional toolbar chip if a session is live.

## Shortcuts

Document every File Explorer binding in `SHORTCUT_HELP`.

Already bound (must appear in the help table): Ctrl/Cmd+N, Ctrl/Cmd+Shift+N, Ctrl/Cmd+F, Ctrl/Cmd+A, Alt+←/→, F5, F2, Delete, Esc.

Add: Ctrl/Cmd+C/X/V, Ctrl/Cmd+Shift+C, Enter (open folder or text file), Backspace and Alt+↑ (parent; ignore when typing), Ctrl/Cmd+L or Alt+D (focus path), Shift+F10 (row context menu), Home/End (first/last visible row), Shift+↑/↓ (range select from last clicked index).
